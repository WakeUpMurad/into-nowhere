# TON: публикация и обслуживание

Основной сайт: [into-nowhere.murad-losangeles.workers.dev](https://into-nowhere.murad-losangeles.workers.dev/). React-приложение и TON-сервер опубликованы в одном Cloudflare Worker; заказы хранятся в D1. Создание публичного счёта и открытие выбора кошелька проверены. Бесплатный персональный `TONAPI_KEY` уже добавлен как зашифрованный секрет Cloudflare; приём включён в конфигурации (`PAYMENTS_ENABLED=true`). **Доступ сервера к индексатору проверен: TON API возвращает HTTP 200. Реальный контрольный перевод владельцем ещё не выполнен.** GitHub Pages остаётся демонстрацией без оплаты; Apple Pay, Google Pay, карты и USDT не активированы.

## Сумма и подтверждение

Покупатель выбирает долларовый ориентир от $1. Сервер фиксирует сумму **обычных TON основной сети**, рассчитанную по свежей цене TON/USD и округлённую вверх до целого nanoTON. Источники — CoinGecko, при его недоступности последняя сделка TON/USD у Kraken. Возраст источника не более пяти минут; старый курс не используется для нового счёта. Счёт действует десять минут. USD не означает оплату долларами; сетевую комиссию отдельно показывает кошелёк. Отдельного коммерческого верхнего предела суммы нет; действуют ограничения числового формата, кошелька и сети.

TON Connect передаёт точную сумму, уникальный комментарий `INW-…` и получателя:

```text
UQDwlMjt0fw1LHrUdj8wV4tHOZ-Y5NQEAVgp49F7oJfQpJU6
```

Это mainnet-адрес в формате non-bounceable. Новый кошелёк может быть `nonexist`/`uninitialized`: при первом переводе отсутствие кода способно дать `aborted`, хотя TON зачислены. Сервер допускает только узкий проверенный случай начального зачисления без возврата сообщения. Произвольный неудачный перевод не считается оплаченным. Приватный ключ и seed-фраза получателя серверу не нужны.

Заказ записывается в D1; повтор с тем же ключом идемпотентности возвращает тот же заказ. Приватная квитанция читается с `readToken`, в базе хранится его хеш. Браузер временно сохраняет квитанцию в session storage для восстановления оплаты. Не публикуйте токен или полную приватную ссылку.

Ответ кошелька, анимация и `paid=true` не подтверждают получение денег. Сервер сверяет через TonAPI получателя, native-сумму, комментарий, время и состояние транзакции, выдерживает буфер не менее 30 секунд и сохраняет уникальный хеш. Только серверный `paid` запускает ритуал. Проверка идёт при чтении квитанции и раз в минуту по расписанию при наличии pending-заказов.

Интерфейс проверяет несколько минут, затем предлагает повторную проверку или поддержку. Задержка индексатора не доказывает отказ. Просроченный счёт сохраняется: поздний перевод проверяется по исходной фиксированной сумме. При неверной сумме или комментарии нужна ручная сверка; не повторяйте перевод до выяснения судьбы первого.

## Публикация и доступ

`wrangler.jsonc` содержит текущие публичные идентификаторы Cloudflare, D1, кошелька и email. Токены разрешённого владельцем входа Wrangler сохраняются вне репозитория. В новом окружении войдите в соответствующий аккаунт:

```sh
npm ci
npx wrangler login --scopes-list account:read user:read workers_scripts:write d1:write
```

Для обновления существующего сервиса сначала выполните проверки, затем примените миграции к **существующей** базе и опубликуйте:

```sh
npm test
npm run test:payments
npm run check:payments
npx wrangler d1 migrations apply into-nowhere-payments --remote
npm run deploy:payments
```

Go-проверки `npm run test:api` нужны при изменении карточного сервера. Независимая копия требует своей D1 и её идентификатора и account_id в конфигурации. Рабочую базу не удаляйте и не заменяйте ради обновления сайта.

Платный тариф не подключён: используются бесплатные квоты Workers и D1. Следите за расходованием квот в кабинете Cloudflare; размещение не рассчитано на неограниченную нагрузку. Комиссии сети TON отдельны от хостинга.

В официальном [TonConsole](https://tonconsole.com/) создан серверный ключ «Into Nowhere server»; в его кабинете подтверждён текущий Free-план $0 в месяц, 1 запрос в секунду. Ключ `TONAPI_KEY` уже сохранён зашифрованным секретом рабочего Worker; значение не записано в файлы, Git или чат. При смене ключа его можно добавить интерактивно через `npx wrangler secret put TONAPI_KEY`, затем проверить статус индексатора до контрольного перевода. Дополнительный ключ цены при необходимости добавляется через `npx wrangler secret put COINGECKO_API_KEY`. Не добавляйте ключи в конфигурацию, Vite, Git или чат. `.dev.vars`, `.wrangler/` и `work/` исключены из Git. Ограничивайте доступ к D1 с финансовой историей заказов.

Перед изменением схемы сохраните приватную копию, предварительно создав каталог `work/`:

```sh
npx wrangler d1 export into-nowhere-payments --remote --output work/payments-backup.sql
```

Не публикуйте экспорт. Состояние последней сверки индексатора можно посмотреть без чтения приватных квитанций:

```sh
npx wrangler d1 execute into-nowhere-payments --remote --command "SELECT value FROM payment_service_state WHERE key='ton_scan_status';"
```

Запись содержит `checkedAt`, `outcome` и иногда `httpStatus`. Она показывает выполнение проверки, а не доказывает оплату. Если свежий курс недоступен, новый счёт не создаётся; если индексатор недоступен, заказ остаётся pending.

## Реальная проверка владельцем

1. На физическом телефоне открыть основной сайт, выбрать ориентир $1, создать счёт и сверить адрес выше.
2. Подключить свой mainnet-кошелёк с балансом TON для суммы и комиссии. Просмотреть сумму и комментарий; сам владелец кошелька подтверждает перевод.
3. Сохранить номер заказа и публичный хеш. Дождаться серверного `paid` и ритуала, проверить поступление у получателя и восстановление квитанции после обновления страницы.
4. При задержке повторить проверку. В поддержку передавать номер заказа, хеш и описание, без seed-фразы, ключа и приватного токена.
5. Проверить ручной возврат из кошелька получателя и записать его отдельно. Сайт не отправляет возврат автоматически; текущая TON-схема D1 не меняет заказ на `refunded`.

Автотесты используют контролируемые ответы поставщиков и локальную D1. Pending-счёт и открытие кошелька не заменяют настоящий перевод и проверку его получения.

## 25% помощи и возвраты

Четверть каждого **фактически полученного** платежа до комиссий выделяется на прямую помощь людям. Доля считается в TON. `charityQuarterNanoTON` хранит числитель в четвертях nanoTON: поступление 101 nanoTON создаёт запись `101`, то есть обязательство 25,25 nanoTON. Складывайте числители через BigInt и делите на четыре после суммирования; не округляйте каждый платёж вниз и не используйте плавающую точку.

Pending-счета не являются доходом или помощью. Сверяйте оплаченные заказы с поступлениями и ведите отдельный учёт возвратов, выполненной помощи и остатка обязательства. Комиссии и расходы покрываются из доли сервиса. Полный согласованный возврат отменяет соответствующую долю помощи; история уже оказанной помощи сохраняется. Частичные возвраты требуют точного учёта вне текущей схемы заказов.

Деньги приходят непосредственно оператору. Worker не переводит 25%, не меняет TON, не оказывает помощь и не выполняет возвраты. Оператор фактически отделяет резерв, организует помощь и сохраняет подтверждения. В отчётах показываются поступления, резерв, возвраты, выполненная помощь и остаток; личные истории публикуются только с согласия получателей. Отчётов об оказанной помощи пока нет.
